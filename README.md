# Boolean Expression Minimization Experiments

这是离散数学课程加分题中的一组逻辑表达式化简实验。题目给出 3、5 或 10 个变量的真值表，需要构造一个与真值表等价、尽量简洁的合式公式。

仓库保留了当时从暴力枚举到基于真值表模式合并的几种尝试，因此更适合作为算法探索记录，而不是一个通用的布尔逻辑综合器。

## 1. 暴力枚举

最初的实现直接枚举候选表达式，再对真值表逐行验证。

以 3 变量版本为例，代码会枚举：

- 变量及其否定形式；
- 变量排列顺序；
- `&` / `|` 运算符组合；
- 固定括号结构下的候选公式。

随后通过 `eval()` 在每一行真值赋值上检查候选表达式是否与目标输出一致。

这种办法在 3 个变量时还可以直接运行，但变量数增加后候选数量迅速膨胀。5 变量版本中已经需要持续打印搜索计数来观察运行进度。

这里的“暴力”并不是枚举所有可能的逻辑公式，而是在一组限定的表达式结构中搜索。

## 2. 基于真值表模式的合并尝试

后续代码位于：

```text
2_Quine_McCluskey_Method/
```

这些版本受到 Quine–McCluskey 中“从真值表寻找可合并项”这一思路的启发，但**并不是标准 Q-M 算法的完整实现**。

当前代码主要采用以下方式：

1. 取出真值表中结果为 `1` 的行；
2. 选取两个变量 `i, j`；
3. 寻找在其他变量上取值相同的多行；
4. 观察这组行在 `i, j` 两个变量上的四种取值组合；
5. 将对应模式翻译成更短的二元逻辑关系；
6. 再与其余保持不变的变量组合成表达式。

例如，代码中的 `translate()` 会识别若干两变量真值模式，并输出：

```text
a ∧ b
a ∨ b
a ⊕ b
a ↔ b
a → b
¬a
b
...
```

这种方法能够一次消去或合并部分变量，比直接枚举完整公式更接近从真值表结构本身寻找规律。

## 几个版本的关系

`qm_main_solver.py`、`qm_solver_v2.py` 和 `qm_solver_v3.py` 是当时逐步修改留下的实验版本，并没有整理成统一接口。

其中可以看到几种不同的数据输入方式：

- 直接在源码中嵌入真值表；
- 从 Excel 表格读取；
- 针对 3 / 10 变量规模调整参数。

`qm_main_solver.py` 仍保留了开发时的本地绝对路径，因此如果直接运行，需要把输入文件路径改为仓库中的 `data/真值表.xlsx` 或自己的真值表文件。

## 和标准 Quine–McCluskey 的区别

标准 Q-M 算法通常会反复合并只差一个 bit 的 implicant，并继续生成更高层的 implicant，最终再进行 prime implicant 选择。

本仓库的实现没有完整走完这套流程，也没有实现通用的 prime implicant chart。它更接近：

> **对真值表中的局部模式进行分组，并把可识别的模式替换为更短逻辑关系的启发式化简。**

因此仓库目录保留了原来的 `Quine_McCluskey_Method` 名称，但 README 使用“受 Q-M 思路启发”来描述当前代码。

## 说明

这个项目保留了早期算法探索的痕迹，包括内嵌测试数据、多个实验版本和本地路径。它的主要价值在于记录从“枚举候选公式”转向“直接分析真值表结构”的思路变化，而不是提供一个已经封装完成的通用最小化工具。
